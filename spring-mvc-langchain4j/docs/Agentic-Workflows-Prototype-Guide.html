Agentic Workflows Prototype - Project Guide

Folder spring-mvc-langchain4j/ · Spring MVC 7 (no Spring Boot) + LangChain4j + Claude · Tomcat 11 in Docker

1.Overview

A small learning and reference application that shows the main agentic AI patterns in plain Java, inside a Spring MVC application without Spring Boot - the same style as a typical existing product (Spring MVC + JSP + Tomcat).

  • Ask page - a chat assistant that can call Java methods (tools) and remembers the conversation (memory).
  • Workflows page - four multi-agent patterns: sequence, loop (evaluator-optimizer), parallel and routing, each showing every agent step.
6patterns: tools, memory, sequence, loop, parallel, routing
11workflow agents + 1 assistant
2tools (date/time, order status)
3pages + health check
2-10Claude calls per workflow run
The sibling project appeal-assistant-demo uses the same building blocks for one complete business workflow with human approval and an audit log.

5.How it works (flows)

5.1 Start-up

WebAppInitializer (instead of web.xml) starts Spring with WebConfig, sets UTF-8 and cookie-only sessions. Spring creates ClaudeModel (reads ANTHROPIC_API_KEY; without it the pages show a clear message), ShopTools, AssistantService, WorkflowService (builds the four workflows once) and the controllers.

5.2 Ask page: tools + memory (flowchart)

"New chat" (POST /ask/clear) clears both the chat memory and the page history for this browser.

5.3 Workflows page

The user picks a pattern and enters text. WorkflowService.run() invokes the matching pre-built workflow with the input as a named value (task, code or question), then reads every agent call from the shared state (LangChain4j AgenticScope) to show the steps. Errors are caught and shown as a message on the page.

6.The four workflow patterns

7.ER diagram (data model)

There is no database: all state is in memory and lost on restart. The diagram is the logical model of what the application keeps.

PK / FK as logical keys. CHAT_TURN is what the page shows; CHAT_MEMORY_MESSAGE is what Claude sees again on the next question. ORDER has no relation to the others - it is only read by the getOrderStatus tool.

8.Java classes & relations

Arrows = calls / uses. Both services get the shared ClaudeModel; the routing workflow's OrderAgent and the assistant both use ShopTools.

13.Build & deployment

14.Testing

14.1 Free tests with the fake Claude server

testing/FakeClaude.java imitates the Claude API with believable answers: it asks for getOrderStatus on "order 101", classifies routing questions, returns score 0.5 then 0.9 in the loop, and waits 1.5 s per parallel reviewer to prove they run at the same time.

$env:ANTHROPIC_API_KEY = "test-key"
$env:ANTHROPIC_BASE_URL = "http://fake-claude:18090/v1/"
docker compose --profile fake up -d --build
# ... test at http://localhost:8080/ ...
docker compose --profile fake down
Remove-Item Env:ANTHROPIC_BASE_URL   # back to the real API ...
# ... and set the real key again (the terminal still holds "test-key"):
$env:ANTHROPIC_API_KEY = [Net.NetworkCredential]::new('', (Read-Host 'API key' -AsSecureString)).Password

Every request is logged to testing/requests.log (git-ignored).

15.Security & known limitations

  • All user and AI text is escaped with <c:out>; sessions are cookie-only.
  • The API key lives only in the terminal session and the container environment.
  • Tools are read-only and expose only pretend shop data.
Limitation (deliberate - learning prototype)In a real product
All state in memory; lost on restartDatabase-backed chat memory store
No login, no CSRF protectionSpring Security
No audit log of AI callsAudit + cost logging (see the appeal demo for an audit trail)
Workflows run inside the web request (can take a minute)Background jobs + status page (as in the appeal demo)
Memory window of 20 messages, no expiry for idle sessions' memoryPersistent store with retention rules

16.Cost

Claude Opus 5.5: $4 / $20 per million input / output tokens (October 2026). An Ask question costs about a cent or two; a workflow run 2-10 calls, usually a few cents; the loop is the most expensive. The fake server costs nothing.

17.Troubleshooting

SymptomCause / fix
"ANTHROPIC_API_KEY is not set"Set the key in the same terminal, then docker compose up -d --build.
"Error calling Claude: ... 401" / credit errorsWrong key / add credit in the Anthropic Console.
Workflow page takes longNormal for the loop (several calls); it runs inside the request.
Port 8080 in useAnother app or container uses it (e.g. a local Tomcat) - stop it or change the port in compose.yaml.
"container name already in use"docker rm -f ai-framework-tomcat, then start again.
Calls go to the fake serverRemove-Item Env:ANTHROPIC_BASE_URL, restart with compose.
VS Code shows "non-project file"The Java extension has not imported the Maven project (no local Maven). The app is unaffected.
